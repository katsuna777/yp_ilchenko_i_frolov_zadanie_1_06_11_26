# Чудо Обувь

Приложение **C# / Windows Forms / .NET 8 / MySQL** для каталога обуви и оформления заказов. Данные и изображения взяты из приложенного архива, интерфейс на русском, расчёты в рублях.

## Запуск на Windows

1. Установите и запустите локальный **MySQL Server 8.0.16+** (рекомендуется 8.4). Запомните порт и пароль пользователя MySQL.
2. Для разработки установите **.NET 8 SDK**, откройте `ChudoObuv.sln` в Visual Studio 2022 с компонентом «Разработка классических приложений .NET» или выполните в корне:

   ```powershell
   dotnet run --project src/ChudoObuv.WinForms
   ```

3. В окне подключения укажите сервер `127.0.0.1`, порт `3306`, базу `chudo_obuv`, пользователя MySQL и его пароль. Пароль MySQL нужен только для подключения к серверу; пользователь приложения входит без пароля.
4. При первом запуске нажмите **«Создать и заполнить базу»**. Будут созданы таблицы и загружены все исходные данные. Учётной записи MySQL нужны права на создание базы и таблиц. Существующие таблицы приложение не перезаписывает. Если база уже заполнена, нажмите **«Подключиться»**.
5. Откроется каталог в режиме гостя. Для работы с корзиной нажмите **«Войти»** и введите логин из ресурсов.

Параметры подключения сохраняются локально в `%LOCALAPPDATA%\ChudoObuv\appsettings.local.json`. Файл не входит в репозиторий. При смене компьютера укажите параметры заново. В этой учебной версии доступ к MySQL прямой; роли приложения не заменяют права самой учётной записи MySQL.

Для запуска готового приложения соберите архив:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/publish.ps1
```

Распакуйте **весь** `artifacts/ChudoObuv-win-x64.zip` и запустите `ChudoObuv.exe`. В архив включён .NET Runtime, отдельная установка .NET на целевой машине не нужна. MySQL запускается отдельно. GitHub Actions также собирает этот ZIP в артефактах задания `windows-build`.

## Вход и возможности

| Роль | Пример логина | Возможности |
|---|---|---|
| Гость | без входа | Просмотр каталога, фотографий, состава, описания, цен и доступных размеров |
| Покупатель | `asidorova` | Поиск, фильтры, сортировка, корзина и оформление заказа на своё имя |
| Менеджер | `papetrov` | Возможности покупателя; список заказов, просмотр состава, создание заказа для клиента, удаление |
| Администратор | `isivanov` | Возможности менеджера; редактирование ФИО, даты и состава существующего заказа |

Остальные 17 логинов сохранены из `resources/Users_import.xlsx`. Вход точный, с учётом регистра, без пароля.

В каталоге можно искать по названию, производителю, описанию и составу; фильтровать по категории, подкатегории, производителю, доступному размеру и наличию; сортировать по названию, цене или количеству. Для добавления выберите модель, размер, количество и нажмите «Добавить в корзину».

В корзине можно добавлять модели и размеры, удалять строки и менять число пар в столбце «Количество». До оформления корзина не резервирует товар. При сохранении остаток проверяется повторно. Менеджер и администратор могут изменить ФИО клиента при создании заказа. В окне «Заказы» доступны поиск по ФИО/номеру и просмотр состава; администратору также доступно редактирование. Отчество можно оставить пустым.

## База и правила учёта

`users` → `orders` → `order_items` → `stock_items` → `products` / `sizes`.

- Товарная позиция уникальна по модели и размеру. Количество — число доступных пар. Модель хранит категорию, подкатегорию, производителя, фото, состав, описание и цену. Категории не ограничены обувью, что позволяет в дальнейшем добавить аксессуары.
- Размерный ряд модели определяется строками её товарных позиций; доступные размеры — строками с положительным остатком. В ресурсах нет отдельного размерного ряда каждой модели: он не дополняется выдуманными размерами из общего справочника.
- Цена фиксируется в строке заказа (`DECIMAL(12,2)`); сумма строки и заказа вычисляется из сохранённых цен. При изменении заказа цена уже существующей позиции сохраняется, для новой берётся текущая цена каталога.
- Создание, изменение и удаление заказа выполняются в транзакции InnoDB. Остатки блокируются `FOR UPDATE` в порядке ID и проверяются до списания. При ошибке откатывается весь заказ. Изменение списывает только разницу, удаление возвращает пары в доступный остаток.
- Поле `version` предотвращает перезапись изменений другого сотрудника и повторный возврат остатков при удалении.
- Исторические заказы не списываются повторно при импорте: исходный файл остатков уже содержит количество, **доступное для заказа**.
- Запросы с пользовательскими данными параметризованы. Проверки ролей выполняются в `Store`, а не только видимостью кнопок.

Схема находится в `database/schema.sql`, заполнение — в `database/seed.sql`. SQL встраивается в приложение, поэтому для создания базы исходники рядом с EXE не нужны. При ручном импорте сначала создайте базу UTF-8 в MySQL Workbench, выберите её, затем последовательно выполните оба SQL-файла. Исправления сопоставления исходных данных описаны в [docs/import.md](docs/import.md).

## Проверка

```powershell
dotnet build ChudoObuv.sln -c Release
$env:CHUDO_TEST_HOST = "127.0.0.1"
$env:CHUDO_TEST_PORT = "3306"
$env:CHUDO_TEST_USER = "root"
$env:CHUDO_TEST_PASSWORD = "ваш пароль MySQL"
dotnet run --project tests/ChudoObuv.IntegrationTests -c Release
```

Тесты создают новую базу со случайным именем `chudo_test_*` и удаляют только её в конце. Требуются права `CREATE DATABASE` / `DROP DATABASE`. Проверяются импорт, роли, SQL-инъекция в логине, суммы, списание/возврат остатков, откат многопозиционного заказа, сохранение исторических цен, конфликт версий и конкурентное оформление последней пары. Рабочая база тестами не используется.

В GitHub Actions интеграционные проверки запускаются на MySQL 8.4, сборка и упаковка WinForms — на Windows. Окна WinForms исполняются только на Windows; кросс-сборка на macOS не заменяет ручную проверку интерфейса.

## Структура

- `src/ChudoObuv.Core` — модели, импорт базы, MySQL, роли и транзакции.
- `src/ChudoObuv.WinForms` — формы, созданные кодом: подключение, вход, каталог, корзина/редактор и список заказов.
- `resources` — исходные XLSX, фотографии, иконка и логотип.
- `scripts/generate_seed.py` — воспроизводимое чтение XLSX средствами стандартной библиотеки Python, без выполнения макросов и без дополнительных пакетов.
- `tests/ChudoObuv.IntegrationTests` — выполняемые проверки с настоящим MySQL.
